## Current session (Apr 30, 2026) — fixes + dashboard v2 scaffold

### Cloud chat security + NIM streaming fixes (shipped, same session)

4. **Filesystem leak via Coder model on `/` closed.**
   The Nemotron coder model was emitting `[LIST_DIR: .]` while reasoning,
   and `services/command_service.execute_cloud_commands()` was actually
   running it — leaking the project tree to anyone using the public chat.
   Introduced `_DISABLED_FS_COMMANDS` set covering LIST_DIR / LIST_FILES /
   TREE / READ_FILE / CREATE_FILE / WRITE_FILE / EDIT_FILE / DELETE_FILE /
   MOVE_FILE / MAKEDIRS / SHELL_EXEC / RUN_PYTHON / FETCH_DOCS /
   INSTALL_SKILL / SELF_OPTIMIZE. They are short-circuited at the top of
   the loop and replaced with a generic disabled-stub that does **not**
   echo the path the model asked for. Desktop CLI agent has its own
   tool layer and is unaffected.

5. **Coder system prompt cloud override.**
   `routes/chat_routes.py` appends a "CLOUD MODE OVERRIDE" suffix when the
   coder model is selected from the web, telling the model that
   filesystem/shell tools are disabled. Stops it from wasting tokens on
   tool calls that will get stubbed.

6. **NVIDIA NIM streaming fixed (output was arriving "all at once").**
   Root cause: Nemotron-Super spends most of its budget in
   `reasoning_content` before emitting `content`. We were streaming
   reasoning as `<thinking>…</thinking>`, so the user saw nothing useful
   for several seconds and then the answer appeared as one block.
   `services/llm_service.call_nvidia()` now drops `reasoning_content`
   silently unless the caller passes `expose_thinking=True`. Result:
   content streams chunk-by-chunk the moment Nemotron starts emitting it.
   This also closes a second avenue of the filesystem-leak issue (the
   reasoning trace itself was leaking the model's tool-call planning).

### Scale & correctness — race fix + bulk dialer (shipped)

9. **Outbound dial logic extracted to a service.**
   `services/telephony_dialer.py` (new) owns Vobiz + Exotel dialing. Both
   `routes/telephony_routes.py` (the per-call API) AND the new
   `campaign_worker.py` (bulk dialer) call into it, so there is exactly
   one place where SIP credentials are validated and Firestore mappings
   are written. The legacy `trigger_vobiz_call` / `trigger_exotel_call`
   functions in the route file are now unused but kept for back-compat.

10. **Race condition fixed for simultaneous calls to the same phone.**
    Previously `active_calls/<phone>` was a single doc with latest-wins
    semantics — if customer X started a call to Agent A and another to
    Agent B within the same second, the second `set()` overwrote the
    first and the first call would be answered with Agent B's config.
    Now every webhook AND every outbound dial writes BOTH the legacy
    top-level doc (kept for back-compat) AND a new
    `active_calls/<phone>/pending/<call_uuid>` subcollection entry.
    `livekit_agent.py::_lookup_by_phone` does a Firestore TRANSACTION:
    pulls the OLDEST unclaimed entry, atomically marks it claimed, and
    returns its agent_id. Two simultaneous calls each claim a different
    entry — no collisions possible.

11. **Bulk lead dialer (`campaign_worker.py`) — actually built.**
    `start.sh` was already attempting to launch this file; previously it
    didn't exist so the campaign UI was non-functional. The new worker:
      - Polls `collection_group('campaigns')` every 5s for `status=running`.
      - Per-campaign concurrency cap (`CAMPAIGN_CONCURRENCY`, default 3).
      - Process-global cap across ALL users (`CAMPAIGN_GLOBAL_MAX`, 20).
      - Pacing between dials (`CAMPAIGN_DIAL_PACING`, 0.5s) to avoid
        Vobiz/Exotel burst rate limits.
      - Tracks per-number outcome in `dialed.{phone}` map; resumable
        cleanly when paused/restarted (already-dialed numbers skipped).
      - Marks campaigns `completed` automatically when drained.
      - Graceful SIGTERM/SIGINT shutdown.
    Required env: `PUBLIC_BASE_URL` (or `RENDER_EXTERNAL_URL` /
    `KOYEB_PUBLIC_URL`) so webhook callbacks resolve to a public https URL.

### Zero-silence SIP call experience (shipped)

7. **Worker warm-pool.** `livekit_agent.py`'s `WorkerOptions` now reads
   `LIVEKIT_NUM_IDLE` (default 2) and passes `num_idle_processes=`. Two
   agent processes are kept pre-spawned and pre-connected to LiveKit so
   the moment a job is dispatched there is no cold-start. Falls back
   gracefully on older livekit-agents versions that don't support the
   kwarg.

8. **Optional explicit pre-dispatch (zero silence after pickup).**
   `routes/webhooks_routes.py::vobiz_answer` has two modes now:
   - **Default (safe):** no pre-warm. LiveKit's inbound SIP trunk
     creates the canonical room when audio lands. Single-room guarantee.
   - **Direct dispatch (LIVEKIT_SIP_DIRECT_DISPATCH=1):** generates a
     deterministic room name, pre-creates the LK room with full agent
     config in metadata, optionally explicit-dispatches a named agent
     worker (LIVEKIT_AGENT_NAME=…), then returns SIP XML pointing to
     that exact room. The audio leg arrives into a populated room.
   Direct mode requires the LK SIP inbound trunk dispatch rule to be in
   **Direct** mode (so the SIP user portion is honored as room name).

### LiveKit / SIP / NIM bug fixes (shipped)

1. **SIP double-room dispatch fixed.**
   `routes/webhooks_routes.py::vobiz_answer` no longer pre-creates a
   `voice-<agent>--<uid>` room. The pre-warm was causing the agent
   worker to be dispatched twice (once into the empty pre-warmed room,
   once into the canonical SIP room created by LiveKit's inbound
   trunk dispatch rule), wasting a slot and adding 5–6 seconds of
   ringing. We now only save lookup mappings (`call_mappings`,
   `active_calls` with all phone variants) before returning the SIP
   dial XML — LiveKit creates the real room when the audio leg lands.

2. **`livekit_agent.py` post-call analysis crash fixed.**
   `import re` was missing while line ~599 used `re.sub(...)`, so
   every NIM analysis pass threw `NameError`. Added the import. The
   NIM model id `nvidia/nemotron-3-super-120b-a12b` is intentionally
   kept (confirmed correct by user).

3. **Dashboard "Recent calls" not loading fixed.**
   `loadStudioLogs()` in `static/dashboard.html` was rendering rows
   into a hidden compatibility `<table id="studio-call-log-table">`
   (display:none). Rewired to render `.kt-call-row` cards into the
   visible `#studio-call-log-list` div. New helpers
   `_studioChannelMeta` and `_studioRelativeTime` added.
